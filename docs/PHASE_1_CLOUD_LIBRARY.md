# 第一阶段：云端私人图书馆

## 目标

先让首批用户可以在电脑浏览器中拥有一个可靠、私有、可长期使用的云端书房：上传自己的书、直接阅读、做笔记、继续阅读、按书检索。

**第一阶段不依赖任何大模型 API，也不提供 AI 功能。**

## 用户完成的一次闭环

```text
注册 → 上传自己有权使用的 EPUB/PDF → 自动提取书名与封面
→ 浏览器阅读 → 自动记住位置 → 划线/写感想 → 按书找到笔记
```

## P0 功能

- 账号与私有书库；
- EPUB、文本型 PDF 上传和阅读；
- 浏览器内的阅读位置、书签、真实进度；
- 摘录、个人笔记、按书名索引、回到原文；
- 原书封面、书名作者、人工分类；
- 书名、作者、分类、笔记检索；
- 私有对象存储与完整删除；
- 公开注册、邮箱验证、上传频率与存储额度控制；

## 暂不做

- AI 摘要、AI 问答、Embedding、向量检索；
- OCR 扫描书、扫描 PDF 的文字识别；
- 用户互传书、公共书城、书源抓取；
- 订阅、点数、支付、额度系统；
- 原生 iOS/Android App；
- MOBI/AZW3 的公开兼容承诺。

扫描 PDF 在第一阶段可以作为“浏览器翻页阅读 + 页码书签/笔记”的兼容能力；不能承诺选词、OCR 或全文检索。

## 最小云端架构

```text
浏览器
  │ HTTPS
  ▼
Web / API 应用
  ├── PostgreSQL：账号、书目、进度、书签、摘录、笔记
  ├── 私有对象存储：原书、封面、解析产物
  └── CPU 后台任务：元数据、封面、EPUB/PDF 文本提取
```

第一阶段不需要：GPU、模型 API Key、模型网关、向量数据库或 AI 费用控制。

## 部署顺序

1. 建立托管 PostgreSQL 与私有对象存储；
2. 建立账号、书库和严格的用户数据隔离；
3. 接入上传、封面和元数据提取；
4. 将已有阅读器改为多用户 Web 阅读器；
5. 迁移书签、摘录、笔记与按书索引；
6. 开放公开注册；通过邮箱验证、上传频率、单文件大小和免费存储额度控制风险；
7. 完成删除、备份、跨用户越权、上传失败、恢复与公开注册滥用验证后，持续扩大用户规模；
8. 再根据真实使用情况进入 AI 第二阶段。

## 第二阶段的接口预留

即使第一阶段没有 AI，也要保留后续接入位置：

- `background_jobs`：用于文件解析，未来可扩展 OCR / AI；
- 稳定的章节、段落、页码锚点：未来 AI 回答能引用原文；
- 私有全文索引边界：未来替换为向量检索而不暴露跨用户内容；
- `usage_events`：先记录上传和解析行为，未来再加入 AI 成本与额度。

这意味着第二阶段是“增加能力”，而不是“推倒第一阶段重做”。
