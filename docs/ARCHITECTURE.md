# 产品与架构

## 产品定位

Open Reading Library 不是公共盗版书库，也不是只记录书目的笔记 SaaS。

它是一个**私有文件优先的 AI 阅读工作台**：每个用户导入自己拥有或获授权的书，直接阅读、摘录、写下想法，并在需要时调用托管 AI 完成 OCR、摘要、检索和复习。

## 公开版的三个层次

| 层次 | 面向谁 | 用户是否需要本地 AI / GPU |
| --- | --- | --- |
| 自托管核心 | 重视隐私的个人、团队 | 不需要；可不开 AI，或自带 API Key |
| 托管 Beta | 普通读者 | 不需要；平台异步执行 OCR / AI |
| 团队 / 学校版 | 读书会、公司、教育机构 | 不需要；有组织、配额和管理能力 |

## 目标架构

```text
Web / Mobile Web
        │ HTTPS
        ▼
API 应用（认证、书库、阅读、笔记、搜索）
  ├── PostgreSQL（用户、书目、笔记、权限、任务）
  ├── 对象存储（用户原书、封面、OCR 产物；私有桶）
  ├── Redis / 队列（解析、OCR、封面、AI 摘要任务）
  ├── Worker（隔离运行 Calibre、OCR、文本提取）
  └── AI Provider Adapter（模型、额度、审计、可切换）
```

## 必须改变的原型边界

当前本地原型的 Python `http.server` 与单 SQLite 文件适合个人验证，但不能直接公开部署：

- SQLite / 本地路径必须替换为 PostgreSQL + 私有对象存储；
- 所有资源必须带 `user_id`，每次读取均校验所有权；
- 文件解析必须从 Web 进程移至受限 worker，不能直接处理上传文件；
- 书籍、封面、OCR 文本和备份不得公开访问；
- 不能把用户自己的书默认纳入共享书库或作为 AI 训练数据；
- 原型中的 Telegram 导入、频道来源、私人路径和真实书目数据不进入公开代码或线上产品。

## AI 如何服务没有算力的用户

AI 不是用户本机执行，而是由服务端**异步任务**完成：

1. 用户上传 → 文件进入私有对象存储；
2. Worker 提取元数据、封面和文本；扫描 PDF/MOBI 进入 OCR 队列；
3. 用户显式点击“生成摘要 / 制作复习卡 / 问这本书”；
4. 服务端按用户额度调用模型并保存结果；
5. 任务页展示状态、消耗、错误、重试和删除入口。

这样用户无需 GPU，但产品必须提供：免费额度、任务大小上限、排队反馈、缓存同一用户的结果，以及订阅 / 点数以覆盖成本。

## 最小数据模型

- `users`, `organizations`, `memberships`
- `libraries`, `books`, `book_files`, `cover_assets`
- `reading_positions`, `highlights`, `notes`, `tags`
- `extraction_jobs`, `ai_jobs`, `usage_events`, `credits`
- `audit_events`, `deletion_requests`

每张用户数据表必须拥有 `user_id` 或经由 `library_id` 可严格回溯到用户。

## 版权与隐私原则

- 仅托管用户上传、确认有权使用的文件；
- 不提供受版权保护书籍的发现、下载、转发或公共全文搜索；
- 公共分享仅允许用户选择分享自己写的笔记卡片，默认不含受版权保护的长摘录；
- 删除账户应连带删除原书、衍生文本、封面、向量索引和 AI 产物；
- 公开日志、错误追踪和分析系统必须脱敏，不能记录正文、笔记或签名 URL。
