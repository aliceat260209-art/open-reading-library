# 第一期云端部署决策

## 结论

第一期不租 GPU，也不把所有内容塞进一台裸 VPS。采用“一个应用服务 + 托管数据库 + 私有对象存储”的最小云架构：用户数据能安全长期保存，后续 AI 能力可独立增加，不需要迁移书籍和笔记。

## 最小生产环境

```text
用户浏览器
   ↓ HTTPS + 域名
应用服务（Web / API，CPU）
   ├── 托管 PostgreSQL：账号、书目、进度、书签、摘录、笔记
   ├── 私有对象存储：EPUB、PDF、封面、解析产物
   └── CPU Worker：元数据、封面、文本提取任务
```

不部署：GPU、LLM 服务、OCR 模型、向量数据库、支付系统。

## 为什么不只租一台服务器

单台 VPS 同时存应用、数据库和用户原书，会导致：备份难、硬盘故障风险高、扩容困难、文件权限容易出错。第一期将数据库和原书交给托管私有服务，应用服务器只负责网页与 API，更适合少量真实用户的邀请制测试。

## 租用 / 开通顺序

1. 选择部署地区与云服务商；
2. 注册域名，配置 HTTPS；
3. 创建私有对象存储 bucket；
4. 创建托管 PostgreSQL 与自动备份；
5. 创建 CPU 应用服务和受限后台 worker；
6. 配置密钥、日志、告警、备份恢复演练；
7. 先邀请 5–10 位体验用户，不开放公开注册；
8. 通过隐私、删除、越权访问与上传失败验证后再扩大。

## 选择部署地区时的取舍

- **中国大陆优先**：访问体验更好，但需要按当地要求处理域名备案、隐私与上线流程。
- **海外 / 全球 Beta**：起步集成更快，适合邀请制测试，但中国大陆访问体验可能不稳定。
- **推荐原则**：用户在哪里、数据希望在哪里，就先选哪里；不要为了“以后可能全球化”在第一天就做多地区部署。

## 上线前不能跳过

- 当前公开 GitHub 仓库仅包含产品文档，尚不是可注册的云端服务；
- 必须先完成多用户账号、用户数据隔离、私有上传、对象存储权限和删除流程；
- 不能把当前 Mac 上的 `reading-library` 直接暴露到公网，也不能上传任何现有私人书籍、数据库或笔记。
